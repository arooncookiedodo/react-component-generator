# Commit

변경사항의 의도를 보존하면서 검토 가능한 단위로 안전하게 커밋한다. 이 스킬을 호출한 커밋 요청만으로 별도 확인 없이 실행한다.

## 절차

1. `git status --short`, `git diff`, `git diff --staged`로 수정·삭제·스테이징된 변경사항을 확인한다. 추적되지 않은 파일은 필요한 범위에서 내용을 확인하되, 비밀정보나 생성 산출물이 포함되지 않았는지 주의한다.
2. 최근 커밋 기록과 저장소 지침이 있으면 확인하여 기존 컨벤션을 파악한다. 서로 독립적으로 되돌릴 수 있는 변경은 논리적 단위로 분류하고, 관련 없는 변경은 커밋 대상에서 제외한다.
3. 각 단위에 대해 아래 형식의 한국어 커밋 메시지를 작성한다.

   ```text
   <type>: <한국어 요약>
   ```

   `type`은 변경 의도에 따라 `feat`, `fix`, `refactor`, `chore` 중에서 선택한다. 요약은 변경 결과가 드러나도록 간결하게 작성한다.
4. 각 논리적 묶음의 파일을 명시적인 경로로 스테이징하고, 스테이징된 diff를 다시 확인한 뒤 작성한 메시지로 즉시 커밋한다. 여러 논리적 단위가 있으면 각각 별도 커밋으로 만든다.
5. 생성된 커밋 해시와 메시지를 보고하고, 커밋되지 않은 변경사항이 남아 있으면 함께 알린다.

## 안전 기준

- `.env`, API 키, 토큰, 인증서 등 비밀정보가 의심되는 파일은 스테이징하지 않고 사용자에게 알린다.
- `git add .`처럼 범위가 넓은 명령보다 분석을 마친 파일 경로를 명시한다.
- 커밋을 위해 기존 변경을 수정하거나 삭제하지 않는다.
- 훅 실패나 충돌이 발생하면 원인을 보고하고, `--no-verify` 또는 파괴적인 Git 명령으로 우회하지 않는다.
