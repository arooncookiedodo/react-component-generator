# PR 생성

사용자가 명시적으로 PR 생성 또는 열기를 요청할 때 이 스킬을 사용한다. PR 워크플로에는 두 역할이 있다. 주 에이전트는 작업을 전달하고 결과를 보고하며, 전용 PR 실행 서브 에이전트는 이 스킬을 실행하고 GitHub 변경 작업을 수행하는 유일한 에이전트다.

## 주 에이전트의 작업 전달

주 에이전트에서는 PR 사전 점검이나 GitHub 작업을 수행하지 않는다. 사용자가 PR 생성을 명시적으로 승인했음을 확인한 뒤, 서브 에이전트를 정확히 하나 생성하고 이 스킬의 절대 경로, 저장소 경로, 사용자 요청을 전달한다. 전달 계약은 [references/subagent-task.md](references/subagent-task.md)를 사용한다.

주 에이전트는 PR을 생성·수정·병합하거나 댓글을 남기지 않는다. 실행자의 구조화된 결과를 기다리고, 반환된 URL과 브랜치 쌍을 확인한 뒤 사용자에게 결과를 보고한다. 실행자가 차단 사유를 반환하면, 주 에이전트는 누락된 결정 또는 승인만 사용자에게 요청한다.

## PR 실행 서브 에이전트

전달받은 PR 실행 서브 에이전트라면 워크플로를 직접 완료한다. 다른 에이전트에게 다시 위임하지 않는다.

저장소를 변경하지 않고 현재 브랜치, 작업 트리 상태, 원격 저장소, 업스트림 추적, 기본/대상 브랜치, PR에 포함될 커밋, 기여 가이드 또는 PR 템플릿 지침을 확인한다. 사용자가 해당 작업을 명시적으로 승인하지 않았다면 기본 브랜치에서 PR을 생성하거나, 관련 없는 사용자 변경을 포함하거나, 커밋을 만들거나, 브랜치를 푸시하지 않는다.

대상 프로젝트의 기여자 대상 언어를 기준으로 PR 본문 언어를 선택한다.

- 해외 또는 국제 오픈소스 프로젝트이거나 저장소의 기여 가이드, 이슈, 기존 PR이 주로 영어라면 영문 템플릿을 사용한다.
- 한국 프로젝트이거나 저장소의 기여 가이드, 이슈, 기존 PR이 주로 한국어라면 한국어 템플릿을 사용한다.
- 근거가 충돌하거나 없다면 저장소에 있는 기존 PR 템플릿의 언어를 우선한다. 그마저 없으면 추측하지 말고 사용자에게 사용할 언어를 묻는다.

PR 본문을 작성하기 전에 선택한 템플릿 하나만 읽는다.

- 영문: [references/pull-request-en.md](references/pull-request-en.md)
- 한국어: [references/pull-request-ko.md](references/pull-request-ko.md)

저장소가 제공하는 PR 템플릿의 필수 항목을 준수한다. 선택한 참조 템플릿을 본문 기반으로 사용하고, 저장소에서 요구하는 항목은 삭제하지 않고 추가한다.

사용 가능한 인증된 GitHub 연동 도구 또는 `gh`로 PR을 생성한다. 요청 범위를 넓히지 않는다. 사용자가 명시적으로 요청하지 않았다면 커밋을 수정하거나, 강제 푸시하거나, 저장소 설정을 바꾸거나, PR을 병합하거나, 리뷰어를 지정하거나, 추가 메시지를 게시하지 않는다.

인증, 호스팅, 브랜치 공개 또는 사용자 결정이 필요해 생성할 수 없다면 구체적인 차단 사유를 주 에이전트에 보고한다. 결과가 불확실한 원격 변경 작업을 자동으로 재시도하지 않는다. 먼저 일치하는 PR이 이미 존재하는지 확인한다.

## 결과 계약

PR URL, 번호, 제목, 대상/소스 브랜치, 선택한 템플릿 언어, 최종 본문 전체, 수행한 검증을 반환한다. 생성하지 못했다면 차단 사유와 사용자가 해야 할 최소 다음 작업을 반환한다.
